## 1. Задача

8 камер Xiaomi Yi (MJPEG AVI, 1920×1080 @ 50 fps, запис через Mocap Director) не мають апаратного genlock. Через це:
1. **Зсув (offset):** камери стартують у різні моменти.
2. **Дрейф (drift):** годинники камер / карт захоплення трохи відрізняються, тож зсув росте з часом.

ESP32 блимає світлодіодами (2–4 LED у полі зору кожної камери). Mocap Director пише лог `esp32_flashes.txt`: MASTER-спалах + REGULAR-спалахи з часами за годинником ESP32. **Цей лог і є ground truth.**

**Мета:** для кожної камери знайти функцію `t_esp = a · t_cam + b` (a — дрейф, b — зсув) і показати, що похибка синхронізації становить кілька мс, тобто менше одного кадру (20 мс).

## 3. Пайплайн (і які лекції він закриває)

### 3.1 Автоматичний пошук LED — `led_detect.py`
Замість ручного маркування пікселів:
- Взяти кадр «спалах» і кадр «без спалаху» (або max і median по серії кадрів), порахувати різницю `diff = max − median` (піксельні операції).
- Gaussian blur → бінаризація (**Otsu**) → морфологія → `cv2.connectedComponentsWithStats` або `SimpleBlobDetector` (опційно `HoughCircles`).
- Відфільтрувати блоби за площею й круглістю → ROI кожного LED.
- Fallback: ручні координати з конфігу Mocap Director.

**Лекції:** піксельні операції, фільтрація, бінаризація (ДЗ 8), детекція ознак.

### 3.2 Детекція спалахів — `flash_detect.py`
- Для кожного кадру: середня яскравість у ROI (V-канал HSV або grayscale).
- Нормалізація сигналу, медіанний фільтр по часу.
- Поріг (Otsu по гістограмі значень сигналу або адаптивний) → фронти «увімкнення» → номери кадрів спалахів.
- Кілька LED у камері: об'єднати (усереднення або голосування) → стійкість до засвіток.

### 3.3 Уточнення до точності менше кадру — `subframe.py` ⭐ (інноваційна частина)
Сенсор Xiaomi Yi має **rolling shutter**: рядки зчитуються зверху вниз протягом часу `T_readout`. Тому спалах, що почався посеред кадру, засвічує лише частину рядків.
- У першому кадрі спалаху знайти рядок `r`, з якого починається засвітка (профіль яскравості по рядках у вертикальній смузі навколо LED або по всьому кадру, якщо засвітка помітна).
- `t_flash = t_frame_start(n) + (r / H) · T_readout`.
- `T_readout` спочатку взяти ≈ період кадру (20 мс), потім **оцінити з даних**: підібрати таке значення, що мінімізує залишки регресії в 3.4.
- Альтернатива, якщо LED маленький: частку яскравості в першому кадрі відносно повного спалаху вважати частиною кадру, протягом якої LED світив.
- Чесно описати обмеження: карта HDMI-захоплення може перетаймінговувати кадри.

### 3.4 Зіставлення й регресія — `fit.py`
- Зіставити знайдені спалахи зі спалахами з `esp32_flashes.txt`. MASTER-спалах дає якір; далі зіставлення за найближчим часом або за послідовністю інтервалів.
- Для кожної камери: `t_esp = a · t_cam + b` методом найменших квадратів (опційно RANSAC, щоб відкинути хибні спалахи).
- Вихід: `sync.json` → `{cam_id: {offset_ms, drift_ppm, residual_rms_ms}}`.

## 4. Оцінка — `evaluate.py`

**Протокол:** спалахи кожного тейку ділимо на train (перша половина) / test (друга половина). Модель підганяємо на train, похибку міряємо на test, тобто перевіряємо, що синхронізація тримається з часом.

**Метрика:** RMS і максимальна похибка (мс) між передбаченим і справжнім часом спалаху з ESP32; також міжкамерна похибка (різниця передбачених часів однієї події між парами камер).

**Порівняння (ablation, базові методи):**

| # | Метод | Що показує |
|---|---|---|
| B0 | Вирівнювання за номером кадру (offset = 0) | наївний підхід |
| B1 | Зсув з одного MASTER-спалаху, без дрейфу | чому потрібен дрейф |
| B2 | Offset + drift, точність до кадру | внесок регресії |
| **Ours** | Offset + drift + rolling-shutter-уточнення | внесок субкадрової точності |
| (опц.) | Аудіо-крос-кореляція (хлопок) | якщо записати тейк зі звуком |

**Графіки:** сигнал яскравості LED з позначеними спалахами · залишки vs час для кожного методу · дрейф кожної камери (ppm) · похибка vs довжина тейку.

**Запис даних для оцінки:** 2–3 тейки по 3–5 хв (довгі, щоб дрейф був помітний), спалахи кожні ~2–5 с, різне освітлення (одне світле, одне темніше).

## 8. Ризики

- **Лектор не погодить тему** → перейти на Face Hallucination. Репо з цим планом усе одно лишається для студії.
- **LED замалий / засвічений** → збільшити яскравість або дифузор, брати ROI більшим, використовувати V-канал.
- **Rolling shutter не видно** (спалах довший за кадр або LED займає кілька рядків) → зробити спалах коротким (1–2 мс) і розмістити LED вертикально видовженою смугою або використовувати відбиття на стіні/картоні.
- **Карта захоплення дублює чи губить кадри** → перевірити таймстемпи ffprobe, детектувати дублікати кадрів, описати це у висновках.
